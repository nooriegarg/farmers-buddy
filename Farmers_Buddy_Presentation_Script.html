Farmers Buddy

10-Minute Presentation Script  |  Noorie & Yash

OPENING  ~1 min

Noorie:

Hi everyone. I'm Noorie, and this is Yash. Together we've built a full-stack web application called Farmers Buddy.

So the idea came from a simple observation — farmers in India often don't have easy access to agricultural guidance, market prices, or government schemes. They either don't know where to look, or the platforms that exist are too complicated for them to use.

So we thought — what if we built something simple, role-based, and actually useful for the entire ecosystem? Not just for farmers, but for agriculture officers, domain experts, and admins too.

PROBLEM + SOLUTION  ~1 min

Yash:

To be more specific — the core problems we're solving are:

Farmers have no direct channel to ask questions and get answers from officers or experts. There's no centralized place to see mandi prices, upcoming training sessions, or awareness drives. And managing all of this from the admin side is scattered.

Our platform brings all of this together. Four roles — Farmer, Officer, Expert, and Admin — each with their own dashboard and tools. And everything is connected through one backend.

[Open browser — show Home page]

This is the home page. Clean, role-aware. If you're not logged in, you see the public landing. Once you log in, the app knows your role and takes you to the right place.

TECH STACK  ~45 sec

Noorie:

Quick overview of what we used to build this.

[Open VS Code — briefly show folder structure]

The frontend is built with React — component-based, fast, clean UI using Tailwind CSS for styling. For routing we used React Router.

The backend is Spring Boot — Java-based REST API, running on port 8080. We connect to a MySQL database using Spring Data JPA, which means Hibernate manages the tables for us automatically.

The frontend runs on port 5173, talks to the backend via Axios — and we have a shared Axios instance that automatically attaches the user's role as a header on every request.

Simple, clean, production-style setup.

ARCHITECTURE  ~45 sec

Yash:

The architecture follows a clean three-layer pattern on the backend.

[Show backend folder structure in VS Code — controller / service / repository folders]

Every feature has three files — a Controller that handles the HTTP request, a Service that has the business logic, and a Repository that talks to the database.

So for example — when a farmer submits a query, it goes:

QueryController → QueryService → QueryRepository → MySQL

And the response comes back the same way.

On the frontend, every feature has its own service file — so trainingService.js, queryService.js, and so on — which keeps the API calls separate from the UI components.

It's modular, easy to extend, and very easy to debug.

ROLE HIERARCHY + AUTH  ~1 min

Noorie:

Let's talk about how users get into the system.

[Open Register page]

We have four roles — Farmer, Officer, Expert, and Admin. When you register, you pick your role. Farmer is open to everyone. But if you want to register as an Officer, Expert, or Admin — you need a passkey. This is a basic access control so random users can't claim privileged roles.

[Show the passkey modal briefly]

Now for security — passwords are hashed using BCrypt before they're stored. So the database never holds a plain-text password. During login, we use BCrypt's verify method to compare the input against the hash.

[Switch to Login page]

We also built a transparent migration — any old accounts with plain-text passwords get automatically re-hashed on their next login. No data loss, no manual intervention.

After login, the user object — name, ID, role — is saved in localStorage. And React Router's ProtectedRoute component uses that to guard every page. If you try to access /admin-dashboard as a farmer, you get redirected.

SECURITY + VALIDATIONS  ~30 sec

Noorie:

On the security side — we've covered a few important things.

BCrypt for passwords — already covered.

For route protection — the frontend has a ProtectedRoute component that checks the user's role before rendering any page. Wrong role gets redirected to login.

On the backend, sensitive admin endpoints check an X-User-Role header — which our Axios interceptor attaches automatically on every request.

For input validation — email format is validated on registration, password requires at least 6 characters with uppercase, lowercase, and a digit. Duplicate email registration is blocked with a clear error message.

QUICK Q&A CHEAT SHEET

Question Short Answer
Why Spring Boot? Industry-standard Java framework, built-in REST support, easy JPA integration
Why React? Component-based, fast, great for role-based UIs
How does BCrypt work? It hashes the password with a salt — even same passwords give different hashes. matches() verifies without reversing the hash
Why Tailwind CSS? Utility-first, fast to build with, no separate CSS files
How is route protection done? ProtectedRoute component checks user.role from localStorage before rendering the page
What is JPA / Hibernate? Hibernate maps Java classes to DB tables — @Entity becomes a table, fields become columns
Why localStorage and not JWT? Simpler for a project scope — JWT adds stateless auth which is the next natural upgrade
What is CORS and why did you configure it? Cross-Origin Resource Sharing — needed because frontend (5173) and backend (8080) are on different ports. Browser blocks cross-origin requests without explicit permission
What does ddl-auto=update do? Hibernate auto-creates/updates tables on startup based on entity classes — no manual SQL needed
How does the query flow work? Farmer submits → Officer/Expert replies via PUT endpoint → Status becomes RESOLVED → Both replies visible on the same card

Total estimated time: ~9.5 minutes
